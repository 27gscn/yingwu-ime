# 衡码原生输入法工程方案 v0.3

## 一、文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 衡码原生输入法（Hengma Native） |
| 版本 | 0.3.0-alpha |
| 产品形态 | Windows TSF 输入法（x64＋x86） |
| 核心依赖 | 内嵌 librime 1.17.0 |
| 输入范围 | 单字；2—12 字静态词组 |
| 智能能力 | 无语言模型、无小模型、无云端、无用户学习 |
| 当前阶段 | 源码工程及双架构交叉链接完成，待 MSVC 和真机验收 |

## 二、产品目标与边界

### 2.1 产品目标

1. 保留全拼的低学习门槛；
2. 用结构和部首提供可解释、可手工控制的消歧；
3. 在不使用上下文模型的条件下支持 2—12 字词组；
4. 形成不依赖小狼毫 UI 和安装程序的 Windows 原生输入法；
5. 本地运行，输入内容不离开设备。

### 2.2 明确不做

- 不预测任意长句；
- 不分析用户文档或输入上下文；
- 不训练、下载或调用小模型；
- 不自动学习个人词频；
- 不同步云端词库；
- alpha 阶段不承诺覆盖 Windows 安全桌面、AppContainer 或远程会话的全部场景。

## 三、编码产品规则

### 3.1 单字

```text
full_pinyin [structure] [radical_cue]
```

- 全拼必填；
- 结构码可选；
- 部首码仅在结构码之后使用；
- 结构码集合固定为 `z/s/b/d/p`；
- 部首码优先取常用部首名称拼音首字母，缺失时退回首部件读音首字母；
- 同码候选按固定词典权重排序。

### 3.2 词组

```text
continuous_full_pinyin [pair_1] [pair_2]
pair := structure + radical_cue
```

规则：

1. 词长必须为 2—12 字；
2. 各字全拼直接连接，不插入空格；
3. 同一基础码出现多个候选时，寻找从左到右最早且能够实际分组的歧义字；
4. 对该字追加第一组结构/部首码；
5. 第一组后仍位于同一分组的候选，最多再选择一个可分组歧义字，追加第二组结构/部首码；
6. 不能由两个后缀区分时保留候选列表，不伪造唯一编码；
7. 基础码、一级码和二级码同时保留，用户可按需要逐步加码。

### 3.3 兼容原则

- 0.2 版基础码和常见一级码继续有效；
- 二级码是增量能力，不改变普通输入路径；
- `今天去哪了`和`今天去拿了`批准示例保持 `...zk`、`...ss`。

## 五、系统架构

### 5.1 组件图

```text
┌──────────────── Windows 应用进程 ────────────────┐
│                                                  │
│  TSF Framework                                   │
│       │                                          │
│       ▼                                          │
│  CTextService ── KeyEventSink / CompositionSink  │
│       │                    │                     │
│       │                    └── CCandidateWindow  │
│       ▼                                          │
│  RimeEngine adapter                              │
│       ▼                                          │
│  rime.dll ── hengma.schema.yaml / dictionaries   │
└──────────────────────────────────────────────────┘
```

### 5.2 模块职责

| 模块 | 文件 | 职责 |
|---|---|---|
| COM/TSF 生命周期 | `TextService.*`, `Server.cpp`, `Register.cpp` | 激活、接口、注册、卸载 |
| 按键路由 | `KeyEventSink.cpp`, `KeyHandler.cpp` | 判定吞键、调用 librime、编辑会话 |
| 组合文本 | `Composition.cpp`, `EndComposition.cpp` | 预编辑、提交、取消、焦点切换 |
| 候选窗 | `CandidateWindow.*` | 高 DPI 无激活弹窗、绘制候选 |
| 引擎适配 | `RimeEngine.*`, `Utf.*` | 会话、编码转换、候选快照 |
| 词典编译 | `data-tools/*.py` | 单字结构码、词组递归消歧 |
| 构建/安装 | `CMakeLists.txt`, `scripts/`, `installer/` | 双架构构建、注册、卸载 |

### 5.3 进程模型

alpha 版为 TSF 进程内 DLL。优点是工程简单、响应快；风险是输入法故障会影响宿主应用。稳定版建议将 librime 会话迁移到低权限独立宿主，通过命名管道传输按键和候选快照，TSF DLL 只保留薄适配层。

## 六、输入状态机

```text
Idle
 ├─ 字母 ─→ Composing
 └─ 其他键 ─→ 交给应用

Composing
 ├─ 字母/退格 ─→ 更新预编辑与候选
 ├─ 上下/翻页 ─→ 更新高亮或候选页
 ├─ 数字/空格/回车 ─→ Commit → Idle
 ├─ Esc ─→ Cancel（删除预编辑）→ Idle
 └─ 焦点离开 ─→ Cancel → Idle
```

关键约束：取消组合必须先把 TSF 组合范围置空，再结束组合；否则原始拼音会被错误提交到应用。

### 7.3 质量守则

- 输出顺序确定，同一输入数据应产生相同结果；
- 码仅含 `a-z`；
- 权重至少为 1；
- 不把无法区分的候选假定为唯一；
- 所有生成数据需保留来源、版本和许可证；
- 发布前固定源文件哈希并生成 SBOM。

## 八、模拟评估

固定词典权重被当作使用频率代理；每条记录依次作为“用户意图”，系统自动提交同码最高权重候选，并按加权字符编辑距离计算。

| 模式 | 模拟字级别字率 | 查看前三候选后 |
|---|---:|---:|
| 连续全拼 | 6.6601% | 1.0860% |
| 0.2 一级首差后缀 | 1.2532% | 0.0558% |
| 0.3 最多两级后缀 | 0.2186% | 0.0138% |

边界：该指标不等于真实用户别字率；真实测试还需考虑键入错误、拼音知识、认知负担、未登录词、候选窗阅读和不同领域文本。

## 九、构建与发布

### 9.1 构建矩阵

| 架构 | 作用 |
|---|---|
| x64 | 64 位 Windows 应用与系统文本服务 |
| x86 | 32 位 Office/旧应用兼容 |

两者共用 CLSID/profile GUID，但分别写入对应 COM 注册视图；安装顺序为 x86 后 x64。

### 9.2 产物布局

```text
%ProgramFiles%\Hengma\
  x64\HengmaTSF.dll
  x64\rime.dll
  x86\HengmaTSF.dll
  x86\rime.dll
  data\*.yaml
  docs\...
```

用户缓存位于 `%LOCALAPPDATA%\Hengma\Rime`，卸载默认保留，显式 `-PurgeUserData` 才删除。

### 9.3 发布闸门

没有满足以下条件时，不标记为可公开安装版：

- Windows CI 两架构编译通过；
- 安装、覆盖、卸载、失败回滚通过；
- 至少 5 类应用兼容测试通过；
- 12 小时稳定输入无崩溃或宿主异常；
- DLL 与安装包完成可信代码签名；
- 发布 SHA-256、SBOM、第三方许可清单；
- 安全审查确认不记录用户输入正文。

## 十、测试计划

### 10.1 自动化

- 词组分支算法单元测试；
- 运行时词典格式、行数、码长与关键示例检查；
- PowerShell AST 语法检查；
- Windows CI：x64/x86 MSVC 编译；
- 后续增加 TSF 注册冒烟测试和 RimeEngine 无界面测试程序。

### 10.2 真机应用矩阵

| 类别 | 建议对象 | 重点 |
|---|---|---|
| Win32 | Notepad | 基础组合、候选、焦点 |
| Office | Word/Excel | 复杂文本存储、32/64 位 |
| Chromium | Edge/Chrome | 网页输入框、密码框 |
| Electron | Notion/VS Code | 多进程、缩放、焦点 |
| 控制台 | Windows Terminal | TSF 支持和快捷键冲突 |
| 远程 | RDP | 会话切换、候选位置 |

### 10.3 关键用例

1. `qing → qingz → qingzs` 候选逐步收敛；
2. `jintianqunalezk` 与 `jintianqunaless` 分别唯一定位；
3. 二级码只影响一级残余分支；
4. 退格到空、Esc、切换窗口均不残留拼音；
5. 数字选词、空格、回车、上下、PageUp/PageDown；
6. Ctrl/Alt/Win 快捷键不被输入法截获；
7. 100%、150%、200% DPI 下候选窗不越出工作区；
8. 重复安装两次、卸载两次不产生不可恢复状态。

## 十一、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 进程内 librime 故障 | 影响宿主应用 | alpha 严格测试；稳定版独立宿主 |
| 词典首次编译耗时 | 首次切换延迟 | 安装阶段预编译或展示进度 |
| 结构/部首认知不一致 | 用户输错后缀 | 候选注释、帮助页、允许只用拼音 |
| 二级码增加认知负担 | 学习成本上升 | 只对残余冲突开放，不强制输入 |
| COM 双架构注册复杂 | 部分应用不可用 | CI/真机分别验证两个注册视图 |
| 未签名二进制 | SmartScreen 警告 | 正式发布前 EV/OV 代码签名 |
| 数据许可混合 | 分发合规风险 | 代码、运行库、数据分区声明许可 |
